# M49 — Reconstructing a failed delayed new-context attempt (development only)

## Reproduced learning gap
M48 proved that old-item reviews and novel first encounters could be distinguished and gated by >=24 elapsed hours. But after a later first encounter was **wrong**, the new attempt was stored and the topic reset while the learner was left to compare isolated answers manually. The existing Error Archive displays all attempts, but does not guide explicit rule reconstruction and comparison of what changed between the earlier error, intervening new-context correct answer, and later failure.

## Substantive learner path
1. A read-only source-verified \`failedDelayedCases()\` derives a strict chronological sequence from saved \`Attempt\` data: earlier uncertain first encounter, later correct unhinted first encounter with another current exact-version task in the *same mode, skill and author topic*, and later uncertain first encounter with a third distinct task >=24h after the correct. Uses real first encounters, not repeated-card reviews; source unavailable/withdrawn/version-drift and future records fail closed. Chronology is **not proof** the learner clicked any particular recommendation.
2. If the actual post-submission feedback is the latest independently failed delayed case, it shows a direct **Fehler rekonstruieren** action to the existing Fehlerarchiv, not a separate studio or new competency.
3. In that Archive, first write a rule and the suspected difference **before** seeing the three exact-version comparison cards. Then compare original prompts, immutable saved answers, authored draft answers and contextual explanations; write a revised rule referencing the actual differences. Mechanical length/difference gates require written work but never claim correctness or completion credit.
4. Follow through: if a genuine due review card exists for the failed item, offer that actual due review first (transactional \`saveReviewedAttemptOnce\` unchanged). Otherwise, only offer a *previously unattempted*, same-mode, same-skill, same-topic, current-version authored exercise if one exists; no false fresh-context substitutions. In the regular Error Archive the next unseen same-topic item remains available after real review. Before navigation, re-read persistent state and fail closed on stale/withdrawn/invalid targets.
5. Reflection is intentionally **ephemeral** because the existing strict M35 data/backup contracts have no validated generic slot for error reasoning. It is lost on navigation/reload; the app explicitly says so, never increments a fake remediation counter, and only counts a real subsequent graded \`Attempt\` as objective evidence. A durable writing-error history could be designed later only if approved with versioned backup compatibility and CAS tests.

## Constraints
No schema migration, new IndexedDB store, unvalidated production kind, new grading engine, new studio, CEFR inference, source substitution, external review, merge or deployment. Existing v1/v2/v3 backup, eight stores, historical attempts, original source versions, offline service worker and M35 release gates unchanged. All demonstrative sources still \`DEMO_ONLY\`.

## Acceptance
- Unit: exact three-item chronology, >=24h, wrong-version fail-closed, withdrawn source, same-item review excluded, unrelated mode/topic excluded, hints not transfer, exhaustion honest, and future attempts excluded.
- Browser 1280/360: seed explicitly labeled historical test fixture (two dated first-encounter responses) -> perform actual failed delayed first encounter via normal form and persisted grading -> auto deep-link to Fehlerarchiv -> cold own-rule reasoning before three author source comparisons -> revised explanation -> actual due-card retrieval, with existing CAS -> next genuinely unseen context available (if present), exit unanswered -> verify only real first/review attempts, no fabricated production, reload unchanged.
- Full exact-head content/editorial/Node/TS/Vite, Chromium M01–M49, independent Firefox/WebKit, offline recovery and A→B→A rollback. Report only verified PASS/FAIL.
